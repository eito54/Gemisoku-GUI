# DC対策（再入室スコア復元オフセット）設計

- 日付: 2026-08-22
- ステータス: **設計承認済み・実装待ち**（ユーザーの開始指示を待つ）
- 呼称: **dc対策**
- 関連: 24人スタンド読取モード（`2026-08-22-standings24-mode-design.md`、実装済み）

## 背景と要件（ユーザー発言より）

- 24人スタンドモードは累計値を直接読むため加算が効かない
- →「**前回の点数との差**で加算と似たようなこと」ができるはずというユーザー発想を採用
- プレイヤーが切断→再入室するとゲーム側の累計が0に戻り、上書き読取でアプリ側スコアも消えてしまう問題への対処

## 承認済み設計（案B: 減少検出＋復元オフセット）

### 動作フロー

```
スタンド読取 → 読取値r × 既存オフセットO で候補値算出
  → 前回保存値V(前)と全プレイヤー比較
  ├─ 減少なし → そのまま上書き保存（今まで通り）
  └─ 減少あり → 確認モーダル表示
       ├─「前回値から復元する」: O新 = O旧 + (V前 − 候補値) に更新して保存
       │    ※ 以後の読取は自動的に r + O新 で表示（2度目以降はモーダル出ない）
       └─「読み取った値を使う」: 当該プレイヤーのO を 0 にリセットして保存
```

**数値例**: Taroが115ptで切断→再入室。翌読取0pt → モーダル → 復元でO=115、表示115。
次レース15pt読取 → 自動で 15+115=**130pt**。

### 仕様メモ

- standard12のF1加算フローには影響しない（effectiveTotal時のみ動作）
- F2でも減少検出有効（OCR誤読の検知としても機能）
- オフセットはアプリ再起動後も有効（JSON永続化）、スコアリセットでクリア
- 既知の限定事項: 手動得点編集とオフセットは自動整合しない（v1仕様）

### 保留中の関連課題（本設計とは別対応）

- ステッカー数字の名前誤認識（名前開始位置が統一されている点を活かしたクロップ調整で解決予定）— ユーザーが「今のなし」と保留
